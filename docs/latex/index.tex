\chapter{GEM}

 GEM (Gene-\/\+Environment interaction analysis for Millions of samples) is a software program for large-\/scale gene-\/environment interaction testing in samples from unrelated individuals. It enables genome-\/wide association studies in up to millions of samples while allowing for multiple exposures, control for genotype-\/covariate interactions, and robust inference. ~\newline

\item Change the permission\+: chmod +x GEM\+\_\+2.\+2\+\_\+\+Intel
\end{DoxyItemize}

Option 2\+: Build GEM Library Dependencies ~\newline

\begin{DoxyItemize}
\item C++17 compiler or later
\item BLAS/\+LAPACK. For Intel processors, we recommend that GEM be compiled with an optimized math routine library such as the Intel one\+API Math Kernal Library to replace BLAS/\+LAPACK for optimal performance.
\item Boost C++ libraries. GEM links to the following Boost libraries\+: {\ttfamily boost\+\_\+program\+\_\+options, boost\+\_\+thread, boost\+\_\+system, and boost\+\_\+filesystem} ~\newline

\item Suite\+Sparse Library, download and compile it using CMake.
\end{DoxyItemize}

\hypertarget{index_autotoc_md3}{}\doxysection{\texorpdfstring{Dependencies}{Dependencies}}\label{index_autotoc_md3}
C/\+C++ Compiler
\begin{DoxyItemize}
\item A compiler with C++17 (or later) support is required.
\end{DoxyItemize}

LAPACK and BLAS
\begin{DoxyItemize}
\item The LAPACK (Linear Algebra PACKage) and BLAS (Basic Linear Algebra Subprograms) libraries are used for matrix operations in GEM.
\end{DoxyItemize}

Intel processors\+:
\begin{DoxyItemize}
\item We recommend linking GEM to the Intel one\+API Math Kernal Library (one\+MKL), instead of classical BLAS/\+LAPACK, for a greater performance boost. This can be done by replacing -\/llapack and -\/lblas in the makefile with -\/lmkl\+\_\+gf\+\_\+lp64 -\/lmkl\+\_\+sequential -\/lmkl\+\_\+core before compiling.
\begin{DoxyItemize}
\item It is important to compile with -\/lmkl\+\_\+sequential since GEM already does multi-\/threading across SNPs.
\end{DoxyItemize}
\end{DoxyItemize}

AMD processors\+:
\begin{DoxyItemize}
\item For AMD processors, Open\+BLAS (-\/lopenblas) may be a better alternative.
\end{DoxyItemize}

Boost C++ Libraries
\begin{DoxyItemize}
\item The Boost C++ libraries are used for command-\/line, file management and multi-\/threading purposes.
\item The following Boost libraries are required \+:
\begin{DoxyEnumerate}
\item libboost\+\_\+system
\item libboost\+\_\+program\+\_\+options
\item libboost\+\_\+filesystem
\item libboost\+\_\+thread
\end{DoxyEnumerate}
\end{DoxyItemize}

Eigen Library
\begin{DoxyItemize}
\item The Eigen library is used for linear algebra of dense and sparse matrices.
\end{DoxyItemize}

Suite\+Sparse Library
\begin{DoxyItemize}
\item The Suite\+Sparse library is used for linear algebra operations on dense and sparse matrices. It is particularly utilized in in the GLMM model to fit the null model during association test.
\end{DoxyItemize}

Armadillo Library
\begin{DoxyItemize}
\item The Armadillo library is used for linear algebra of dense and sparse matrices. It is particularly utilized in G × E (Gene-\/\+Environment) interaction test.

\begin{DoxyItemize}
\item \#\#\#\# \doxylink{classKinship}{Kinship} File A file contains nonzero values in a three-\/column format, where the first two columns represent sample identifiers, and the third column indicates the kinship coefficient or genetic relatedness between individuals, or the inbreeding coefficient for the same individual. The scale of the kinship matrix does not matter (e.\+g., you can use two times the kinship matrix, or identity-\/by-\/descent information), as long as the values are on the same scale of the diagonal elements to be added in --kin-\/diag. For genetic relationship matrices computed from genotypes that have different values on the diagonals, we recommend specifying all diagonal values explicitly in the kinship file, along with --kin-\/diag 0.

\item \#\#\#\# Genotype Files ~\newline


\href{https://www.well.ox.ac.uk/~gav/bgen_format/spec/latest.html}{\texttt{ {\bfseries{BGEN}}}} ~\newline
 Variants that are non-\/biallelic should be filtered from the BGEN file. Note that since there are no indication of a REF/\+ALT allele in the BGEN file, the second allele is the effect allele counted in association testing. ~\newline


A \href{https://www.well.ox.ac.uk/~gav/qctool_v2/documentation/sample_file_formats.html}{\texttt{ .sample file}} is required as input when the .bgen file does not contain a sample identifier block. ~\newline
~\newline


\href{https://www.cog-genomics.org/plink/1.9/}{\texttt{ {\bfseries{Plink BED}}}} ~\newline


\href{https://www.cog-genomics.org/plink/2.0/formats\#fam}{\texttt{ \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}.fam\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}}} -\/ The .fam file can be space or tab-\/delimited and must contain at least 2 columns where the first column is the family ID (FID) and the second column is the individual ID (IID). GEM will use the IID column for sample identifier matching with the phenotype file. ~\newline


\href{https://www.cog-genomics.org/plink/2.0/formats\#bim}{\texttt{ \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}.bim\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}}} -\/ The .bim file can also be space or tab-\/delimited and should be in the following order\+: the chromosome, variant id, cM (optional), base-\/pair coordinate, ALT allele, and REF allele. ~\newline


\href{https://www.cog-genomics.org/plink/2.0/formats\#bed}{\texttt{ \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}.bed\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}}} -\/ A bed file must be stored in variant-\/major form. The ALT allele specified in the .bim file is the effect allele counted in association testing. ~\newline
~\newline
 ~\newline


\href{https://www.cog-genomics.org/plink/2.0/}{\texttt{ {\bfseries{Plink 2.\+0 PGEN}}}} ~\newline


\href{https://www.cog-genomics.org/plink/2.0/formats\#psam}{\texttt{ \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}.psam\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}}} -\/ The .psam file is a tab-\/delimited text file containing the sample information. If header lines are present, the last header line should contain a column with the name \#\+IID (if the first column is not \#\+FID) or IID (if the first column is \#\+FID) that holds the individual ID for sample identifier matching with the phenotype file. All previous header lines will be ignored. If no header line beginning with \#\+IID or \#\+FID is present, then the columns are assumed to be in .fam file order. ~\newline


\href{https://www.cog-genomics.org/plink/2.0/formats\#pvar}{\texttt{ \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}.pvar\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}}} -\/ The .pvar file is a tab-\/delimited text file containing the variant information. If header lines are present, the last header line should start with \#\+CHROM. If \#\+CHROM is present, then the columns POS, ID, REF, and ALT must also be present. All previous header lines will be ignored. If the .pvar file contain no header lines beginning with \#\+CHROM, it is assumed that the columns are in .bim file order. ~\newline


\href{https://www.cog-genomics.org/plink/2.0/formats\#pgen}{\texttt{ \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}.pgen\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}}} -\/ The .pgen file should be filtered for non-\/biallelic variants. The ALT allele specified in the .pvar file is the effect allele counted in association testing.
\end{DoxyItemize}
